# dsa-java

My DSA journey in Java: solutions, tests, and a progress tracker driven by a Gemini mentor skill.

Everything revolves around one file, `progress.yaml`. The mentor (Gemini skill in `skill/dsa-mentor/`) teaches and
emits a `dsa-snapshot` block after each stage. A small script merges that snapshot into `progress.yaml`, and the
dashboard below is generated from it.

## Quick start

Prerequisites: Java 21+, Maven 3.9+, Python 3.10+ with PyYAML (`pip install pyyaml`), Git.

```bash
python scripts/dsa.py status      # on Windows you may need `py` instead of `python`
mvn -q test                       # confirms the Java toolchain works (no tests yet is fine)
```

## The session loop

1. **Start.** Run `python scripts/dsa.py export` and paste the printed `dsa-snapshot` block as your first message to
   the skill. On your very first session, send nothing and let the mentor start fresh.
2. **Learn.** Work through the stages with the mentor (one step per reply).
3. **Code.** For each practice problem:
   ```bash
   python scripts/dsa.py new 3                  # scaffolds solution + JUnit test (title/module come from the bank)
   # paste your accepted LeetCode Solution class into the new file, fill in the test cases
   mvn -q test
   python scripts/dsa.py solved 3 --attempts 2 --hints 1
   ```
   For problems outside the bank add `--title "..." --topic "Sliding Window" --module 2`.
4. **Save.** Copy the snapshot the mentor emits (after Stage 2, Stage 3, Stage 5, or when you say "save"), then:
   ```bash
   python scripts/dsa.py snapshot snap.txt                       # from a file
   Get-Clipboard | python scripts/dsa.py snapshot                # Windows PowerShell
   pbpaste | python3 scripts/dsa.py snapshot                     # macOS
   xclip -o -selection clipboard | python3 scripts/dsa.py snapshot   # Linux
   ```
   Without a file or pipe, paste into the terminal and press Ctrl-D (Ctrl-Z, then Enter, on Windows).
5. **Commit.** `git add -A && git commit -m "dsa: <topic>" && git push`.

Homework rule from the mentor: solve it on LeetCode alone, no AI hints, then bring the code back for review.

## Commands

| Command | What it does |
|---|---|
| `python scripts/dsa.py snapshot [FILE]` | Merge a pasted `dsa-snapshot` into `progress.yaml`, then refresh outputs |
| `python scripts/dsa.py export` | Print a snapshot to paste into the skill at the start of a session |
| `python scripts/dsa.py new LC [--title --module --topic]` | Scaffold `src/main/java/dsa/mNN/<topic>/LcNNNN...java` and its test |
| `python scripts/dsa.py solved LC [--attempts N --hints N]` | Mark a problem solved |
| `python scripts/dsa.py due` | Spaced reviews that are due or coming up |
| `python scripts/dsa.py status` | One-line progress summary |
| `python scripts/dsa.py dashboard` | Rebuild the README block, `mistakes.md` and `docs/progress.json` |
| `python scripts/build_curriculum.py` | Rebuild `curriculum/curriculum.json` after editing the skill's reference files |

Set `DSA_TODAY=2026-12-01` to pretend it is another day (useful for testing review dates).

## Layout

```
progress.yaml            source of truth (topics, reviews, weak areas, problems, history)
mistakes.md              generated mistakes log
curriculum/              curriculum.json: 11 modules, 60 topics, practice bank (generated from the skill files)
src/main/java/dsa/       solutions, one package per module and topic (dsa.m02.sliding_window)
src/test/java/dsa/       JUnit 5 tests
scripts/                 dsa.py (CLI), build_curriculum.py
docs/progress.json       generated data for the dashboard web page (see docs/SPEC-dashboard.md)
skill/dsa-mentor/        the Gemini skill source: SKILL.md + references/
.github/workflows/       dashboard.yml (rebuilds the README block), ci.yml (mvn test)
AGENTS.md                brief for coding agents working on this repo
```

## The skill

`skill/dsa-mentor/` is the source of truth for the mentor. To update it in Gemini: Settings, Skills, upload the
folder (or paste `SKILL.md` and attach the files in `references/`). Keep a copy here because the hosting platforms
change. After editing `references/*.md`, run `python scripts/build_curriculum.py`.

## Notes

- The generated test files are empty templates and pass vacuously until you add assertions.
- The dashboard workflow is a safety net for edits made in the GitHub web editor; the CLI already refreshes the
  README locally.
- Plan: a static dashboard page served by GitHub Pages from `docs/` (Settings, Pages, Deploy from branch, `/docs`).
