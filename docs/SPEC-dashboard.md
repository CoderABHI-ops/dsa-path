# SPEC: DSA Progress Dashboard Web Page

## 1. Goal and Non-Goals
- **Goal:** A zero-build, single-page static dashboard served via GitHub Pages from `/docs` (and viewable locally) that visualizes personal DSA learning progress, spaced review schedules, curriculum module status, and recent LeetCode solutions at a glance from `docs/progress.json`.
- **Non-Goals:**
  - Client-side data authoring or mutations to `progress.yaml` (read-only visualization).
  - Backend API servers, databases, user authentication, or cloud hosting beyond GitHub Pages.
  - Node.js/npm build steps, bundling (Webpack/Vite), TypeScript compilation, or CSS preprocessors.
  - External runtime CDN dependencies or third-party tracking scripts.
  - In-browser code execution or full LeetCode problem statement rendering.

## 2. Constraints
- **Static Only:** Built exclusively with vanilla HTML5, CSS3, and modern ES2020+ JavaScript. No build step, no npm/package dependencies, no external CDN requirements.
- **Data Source:** Must fetch data via relative URL `fetch("progress.json")` so it operates identically on GitHub Pages (`/docs`) and local static servers.
- **Contract Invariance:** Never rename or remove fields from `scripts/dsa.py` output; changes must be strictly additive.
- **Performance Budget:** Total uncompressed asset footprint (HTML + CSS + JS + inline assets) must be under 100 KB excluding `progress.json`.
- **Accessibility & UX:** WCAG 2.1 Level AA contrast compliance. Full keyboard accessibility (Tab, Enter, Space) with visible focus rings (`:focus-visible`). Progress indicators must use `role="progressbar"`, `aria-valuenow`, `aria-valuemin="0"`, `aria-valuemax="100"`, and `aria-label`. Status must not be conveyed by color alone.
- **Security & Privacy:** No API keys, credentials, or personal identifying information (PII) stored in markup or script.

## 4. Panels (in display order)

### 1. Header
- **Purpose:** Identity, last update indicator, current streak, and generation timestamp.
- **Data Used:** `state.last_updated`, `generated_for`, `overall.streak_days`.
- **Empty State:** `state.last_updated` missing $\to$ "No sessions yet"; streak shows "0 days"; date shows `generated_for`.
- **Interactions:** Static banner with theme toggle support.

### 2. Today
- **Purpose:** Immediate actionable agenda for the day: reviews due now and current topic resumption card.
- **Data Used:** `reviews_due[]`, `reviews_upcoming[]`, `state.current_topic`, `state.module_number`, `state.topic_status`.
- **Empty State:** Reviews list shows "No reviews due today 🎉"; active topic shows "No active topic. Start a session with your mentor."
- **Interactions:** Badge highlighting `days_overdue > 0` (e.g., "Overdue 2d"); upcoming 7-day review sub-list.

### 3. Overall
- **Purpose:** High-level metrics for syllabus topic coverage, practice bank completion, and active days.
- **Data Used:** `overall.topics_done`, `overall.topics_total`, `overall.bank_solved`, `overall.bank_total`, `overall.problems_solved_total`, `overall.active_days`.
- **Empty State:** Progress bars at 0% (`aria-valuenow="0"`), displaying "0/60 (0%)" and "0/175 (0%)".
- **Interactions:** Visual progress bars with percentage and ratio labels.

### 4. Modules
- **Purpose:** Granular tracking across all 11 curriculum modules and individual topic progression.
- **Data Used:** `modules[]` (`number`, `name`, `topics_total`, `topics_done`, `topics_in_progress`, `topics[]`).
- **Empty State:** 11 module rows with 0% progress; topics marked with "todo" status.
- **Interactions:** Expandable/collapsible topic list per module (`<details>` or accessible toggle). Status shown via text badge and distinct icon (✓ completed, ⏳ in_progress, ○ todo).

### 5. Activity
- **Purpose:** Consistency tracker showing daily activity across the last 26 weeks.
- **Data Used:** `activity` (`date: count`).
- **Empty State:** 26-week empty grid of neutral cells; text label "0 active days logged".
- **Interactions:** Hover/focus tooltip on day cells showing date and activity count. Screen-reader text fallback summarizing active day count.

### 6. Practice
- **Purpose:** Display up to 10 recently solved LeetCode problems with attempt counts, hint metrics, and bank status.
- **Data Used:** `recent_solved[]` (`id`, `title`, `difficulty`, `group`, `attempts`, `hints`, `first_solved`, `in_bank`, `path`).
- **Empty State:** "No problems solved yet. Scaffold your first problem with python scripts/dsa.py new <lc>."
- **Interactions:** Colored difficulty pills (Easy: green, Medium: yellow/amber, Hard: red). Tooltip or badge for attempts and hints.

### 7. Focus
- **Purpose:** Consolidate active learning hurdles: weak areas, assigned homework, and recent mistakes log.
- **Data Used:** `weak_areas[]`, `homework[]`, `mistakes_recent[]`.
- **Empty State:** "No weak areas recorded", "No homework assigned", "No mistakes logged yet."
- **Interactions:** Expandable `<details>` accordion for the mistakes list (displaying date and text).

### 8. Patterns
- **Purpose:** Summary table of algorithmic pattern mastery and subjective confidence.
- **Data Used:** `patterns` (`pattern_name: { questions_solved, confidence }`).
- **Empty State:** "No pattern evaluations logged yet."
- **Interactions:** Table or card grid with confidence tags (High, Medium, Low).

## 5. Layout and Visual Design Guidance
- **Layout:** CSS Grid/Flexbox container with `max-width: 1200px` and responsive auto-fit cards.
- **Breakpoints:**
  - *Desktop (> 1024px):* 2-column layout (Left: Header, Overall, Modules; Right: Today, Practice, Activity, Focus, Patterns).
  - *Tablet (768px – 1024px):* Single column with 2-up metric grids.
  - *Mobile (< 768px):* Single column stack, touch targets $\ge 44 \times 44\text{px}$, tables horizontally scrollable.
- **Themes:** Dual-theme via CSS custom properties supporting automatic `prefers-color-scheme: dark` and `light`.
- **Typography & Colors:** System font stack (`system-ui, -apple-system, sans-serif`); monospace for problem IDs (`LC 3`). WCAG AA contrast ratio $\ge 4.5:1$ for body text, $\ge 3:1$ for large headings and UI borders.
- **Accessibility:** Visible `:focus-visible` outlines (`2px solid var(--accent)`). Semantic HTML elements (`<header>`, `<main>`, `<section>`, `<details>`).

## 6. States
- **Loading:** Subtle spinner or skeleton placeholder while `fetch("progress.json")` is in flight.
- **Error:** Clear banner if fetch fails (404, CORS on `file://`, JSON parse error) displaying:
  *"Unable to load progress.json. Run `python scripts/dsa.py dashboard` and serve via a local HTTP server (e.g. `python -m http.server 8000 -d docs`)."*
- **Empty:** Clean zero-state rendering using seed data (`overall` with 0s, `state: {}`, empty arrays). Code must safely use optional chaining (`data.state?.current_topic`) to avoid JavaScript runtime exceptions.
- **Populated:** Full rendering with calculated progress bars, overdue alerts, recent problem cards, and populated heatmap.

## 7. Local Development and Deployment
- **Local Dev:** Direct `file://` access causes browser CORS blocks on `fetch()`. Run a zero-dependency local static server:
  ```bash
  python -m http.server 8000 -d docs
  # Open http://localhost:8000 in browser
  ```
- **Deployment:** Hosted on GitHub Pages via the `/docs` folder on branch `main`. Workflow `.github/workflows/dashboard.yml` triggers regeneration on changes to `progress.yaml`.

## 8. Acceptance Criteria
- [ ] Page operates strictly from static assets (`index.html`, `style.css`, `app.js`) without bundlers or CDN imports.
- [ ] Successfully fetches and parses `progress.json` via relative path on localhost and GitHub Pages.
- [ ] Total uncompressed asset payload is under 100 KB (excluding `progress.json`).
- [ ] Displays all 8 panels in the exact specified order.
- [ ] Progress bars have `role="progressbar"`, valid `aria-valuenow`, `aria-valuemin="0"`, `aria-valuemax="100"`, and `aria-label`.
- [ ] All interactive modules/accordions are keyboard accessible (Tab, Enter, Space) with visible focus rings.
- [ ] Zero JavaScript console errors when loaded with empty/seed `progress.json` (`state: {}`).
- [ ] Gracefully presents error banner when `progress.json` is missing or invalid.
- [ ] Automatic light/dark mode adaptation via `prefers-color-scheme` with WCAG AA compliant contrast.
- [ ] Lighthouse accessibility score $\ge 90$.
- [ ] Contains no personal secrets, tokens, or PII.

## 10. Open Questions (Proposed Additions to `scripts/dsa.py`)
1. **Global Difficulty Breakdown:** `scripts/dsa.py` only outputs `difficulty` on `recent_solved` (max 10 items). Proposed addition: add `overall.difficulty_counts: {"easy": X, "medium": Y, "hard": Z}` to allow a global difficulty breakdown chart.
2. **Nullable State Schema:** In seed data, `state` is `{}`. Proposed addition: emit explicit nulls (`{"module_number": null, "current_topic": null, ...}`) in `scripts/dsa.py` for strictly typed JSON consumers.
3. **Review Completion Action:** Consider adding a CLI command `python scripts/dsa.py review-done <topic>` to clear reviews directly from the terminal.
